\section{INTRODUCTION}
Information is the power in the present day. 
Information and data should be protected from 
unauthorized access, distortion, or any 
unauthorized activity. 

Cryptography is the study of secret writing. Information is 
no longer hidden due to the existence of network adversaries. 
Our communication channel is completely unstable; a third 
party might covertly eavesdrop and obtain information from 
the network or from the channel. Here, cryptography is crucial 
in preventing unauthorized access to our data. Using key(s), 
cryptography converts plaintext messages into unreadable ciphertext 
and vice versa. Encryption is the process of employing a key(s) 
to transform the original message into an unintelligible format, 
while decryption is the act of using a key(s) to convert the 
cipher text back to plaintext. The messages can only be encrypted 
or decrypted by the authorized user.

The project's objective is to examine encrypted text files to 
find and categorize their cipher types using artificial neural 
networks. The cipher algorithm classification model is based 
on the steps: 
\begin{enumerate}
    \item   Creation of a collection of cipher texts with various cipher texts.
    \item   Building a Deep Neural Network (DNN) and training 
            it with a variety of cipher texts and training parameters 
            to enable accurate learning and cipher text classification. 
    \item   Using the trained model to determine the algorithm 
            that might have been used to generate the cipher text. 
\end{enumerate}

Below are the ciphers which we used to generate our dataset:  

\begin{itemize}
    \item \textbf{Caesar Cipher} – The Caesar cipher is a simple 
    substitution cipher that replaces each letter in a message 
    with a different letter based on a fixed shift value. The 
    shift value determines how many letters to the right or 
    left each letter in the message is replaced with. For example, 
    if the shift value is 3, the letter “A” 
    would be replaced with “D”, and the letter “B” would be replaced with “E”.  


    The Caesar cipher can be represented using the following 
    formula, where the input message is represented by the variable 
    “m” and the shift value is represented by the 
    variable “k”: 

    \begin{equation} 
        \textbf{c = (m + k) \% 26}  
    \end{equation}
    
    \item \textbf{Affine Cipher} – The affine cipher is a type 
    of substitution cipher that uses a combination of linear 
    and modular arithmetic to encrypt and decrypt messages. 
    It uses two keys, a and b, to determine how each letter 
    in the input message is replaced with a different letter 
    in the output message. The affine cipher can be represented 
    using the following formula, where the input message is 
    represented by the variable “m”, the key “a” is a number 
    that is coprime to 26, and the key “b” is any number between 
    0 and 25: 

    \begin{equation}
        \textbf{c = (a*m + b) \% 26}
    \end{equation}
      
    \item \textbf{Vigenère Cipher} – The Vigenère cipher is a 
    polyalphabetic substitution cipher that uses a keyword to 
    encrypt and decrypt messages. The keyword is repeated to 
    create a key that is the same length as the input message, 
    and each letter in the message is replaced with a different 
    letter based on the corresponding letter in the key. 
    The Vigenère cipher is considered to be more secure than 
    the Caesar cipher and the affine cipher, as it uses a different 
    substitution for each letter in the message. The Vigenère 
    cipher can be represented using the following formula, where 
    the input message is represented by the variable “m”, the 
    keyword is represented by the variable “k”, and the length 
    of the message is represented by the variable “n”: 

    \begin{equation}
        \textbf{c = (m + k) \% 26}
    \end{equation}
    

    \item \textbf{Monoalphabetic Substitution Cipher} – The 
    monoalphabetic substitution cipher is a type of substitution 
    cipher that uses a fixed mapping of letters to encrypt and 
    decrypt messages. Each letter in the input message is replaced 
    with a different letter according to the fixed mapping, 
    but the mapping does not change for different letters in 
    the message. This means that the same letter in the input 
    message will always be replaced with the same letter in 
    the output message.  

    The monoalphabetic substitution cipher is less secure than 
    the Caesar cipher, the affine cipher, and the Vigenère cipher, 
    as it only uses a single substitution for each letter in the message.

    \newpage

    \item \textbf{Rail Fence Cipher} – The rail fence cipher 
    is a simple transposition cipher that is used to encrypt 
    and decrypt messages by rearranging the letters in the input 
    message. The rail fence cipher is based on the idea of writing 
    the message on a grid of squares, with each letter in the 
    message written in a different square. The message is then 
    read off the grid in a zig-zag pattern, starting from the 
    top left corner and moving to the right and then down.  

    The rail fence cipher can be represented using the following 
    formula, where the input message is represented by the variable 
    “m” and the number of rows in the grid is represented by 
    the variable “n”:   

    \begin{figure}[h!]
        \centering
        \includegraphics[width=0.7\linewidth]{Pictures/Preliminaries/Rail_fence.png}
    \end{figure}

    This formula shows how the letters in the input message are rearranged to create the encrypted message
\end{itemize}

\section{LITERATURE SURVEY}

Over recent years, artificial neural networks (ANNs) have 
come to prominence. Applications and research areas for ANNs 
are numerous and diverse. Their primary objective is the quick 
filtering, classification, and processing of (mainly) non-linear 
data, such as speech recognition, picture processing, and language 
translation. In addition, researchers were able to “train” ANNs 
to play games (e.g. AlphaStar~\cite{AlphaStar:online}) or produce 
artwork in the manner of well-known artists.

On the MysteryTwister C3\cite{Welcomet7:online} (MTC3) website 
in late 2019, Stamp posted a challenge titled “Cipher ID”. The 
task is to identify the type of cipher used to encrypt each 
of the 500 ciphertexts in the collection, which were encrypted 
using 5 distinct ciphers and random keys. The individual ciphertexts 
were then mixed up after each cipher type had been employed 
exactly 100 times. All prior solvers completed the task by deciphering 
the ciphertexts using solvers for the 5 various cipher types, 
despite the author's goal of encouraging others to begin research 
in the fields of machine learning and cipher type detection. 
The participants were able to determine the type of encryption 
the algorithm that was employed after learning the plaintext of each cipher.

We worked on the cipher text detection problem with the help of ANN 
and in this process, TensorFlow and Pytorch were used. TensorFlow 
is a free and open-source data flow and math library developed 
by Google written in Python, C++, and CUDA, and was publicly
released in 2015. PyTorch is an open-source machine learning (ML) 
framework based on the Python programming language and the Torch 
library which was initially released in the year 2016.

\section{PROPOSED WORK}
\subsection{Dataset Generation}
The dataset has been generated for five types of ciphers:
\begin{itemize}
    \item Caesar

    \item Vigenère
    \item Substitution

For Data Preprocessing, we converted text to lowercase and removed 
all whitespaces and punctuation.

Each of the classes has 6815 data points, resulting in a total 
of 34075 data points and each data point consists of the ciphertext

We wrote a Python script for each of the ciphers to encrypt 
the data into a Pandas DataFrame. The combined DataFrame is shuffled and 
exported as a CSV file for the resulting dataset.

\subsection{Model using CNN}

The main intuition behind this method is that CNN uses its kernel 
as a “local receptive field”, which means that a CNN kernel 
(small in size as we are dealing with stream cipher and not 
block cipher) can look at its nearby characters and will find 
some pattern in the ciphertext

So, we first converted every ciphertext into their respective 
list of tokens using a  TextVectorizer, then we converted that 
list into a 2D text matrix as follows:

\begin{figure}[h!]
    \centering
    \includegraphics[width=0.4\linewidth]{Pictures/CNN_Model/string_conversion.png}
    \caption{Converting text to 2D text matrix}\label{fig1:convert_text_img}
\end{figure}

Note that this conversion depends on the length of the string 
used, i.e.\ for a string for length $n$, we will generate a 
$n \times n$ matrix”. After we generate all variable-sized matrices, 
we resize them to $60 \times 60$ using Bilinear Interpolation.

Now we can see that a kernel (say $3 \times 3$ with stride one) 
can observe its previous as well as its next character and can 
use that information to find patterns in the ciphertext.

We use a CNN to extract features from the matrix and then we 
feed those features to a Dense Network to classify between the 
ciphertext types.

\subsection{Model using Transformer}  

The Transformer in NLP is a novel architecture that aims to 
solve sequence-to-sequence tasks while handling long-range dependencies 
with ease. The Transformer was proposed in the paper Attention 
Is All You Need~\cite{https://doi.org/10.48550/arxiv.1706.03762}.

\hfill

Quoting from the paper:

“The Transformer is the first transduction model relying entirely 
on self-attention to compute representations of its input and 
output without using sequence-aligned RNNs or convolution.”

\hfill

Here, “transduction” means the conversion of input sequences 
into output sequences. The idea behind Transformer is to handle 
the dependencies between input and output with attention and 
recurrence completely.
  
\begin{figure}[h!]
    \centering
    \includegraphics[width=\linewidth]{Pictures/Transformer_Model/transformer_arch.jpg}
    \caption{Transformer architecture}\label{fig2:transformer_arch}
\end{figure}  

\newpage

The encoder and decoder blocks are actually multiple identical 
encoders and decoders stacked on top of each other. Both the 
encoder stack and the decoder stack have the same number of units.

\hfill

The number of encoder and decoder units is a hyperparameter.

\begin{figure}[h!]
    \centering
    \includegraphics[width=0.5\linewidth]{Pictures/Transformer_Model/Encoder-Decoder.png}
    \caption{Encoder Decoder Stacks}\label{fig2:encoder_decoder}
\end{figure}  

This is how it works:  

\begin{itemize}
    \item The word embeddings of the input sequence are passed 
    to the first encoder
    \item These are then transformed and propagated to the next encoder
    \item The output from the last encoder in the encoder-stack 
    is passed to all the decoders in the decoder-stack as shown 
    in the figure below:
\end{itemize}  

In addition to the self-attention and feed-forward layers, the 
decoders also have one more layer of Encoder-Decoder Attention layer. 
This helps the decoder focus on the appropriate parts of the input sequence.

\begin{figure}[h!]
    \centering
    \includegraphics[width=0.5\linewidth]{Pictures/Transformer_Model/transformer_working.png}
    \caption{Transformer Working}\label{fig2:transformer_working}
\end{figure} 

According to the paper:

\hfill 

“Self-attention, sometimes called intra-attention, is an attention 
mechanism relating different positions of a single sequence 
in order to compute a representation of the sequence.” 

\newpage

\hfill

Consider the following sentence as an input sentence we are 
feeding into a transformer:

\hfill 

\textbf{”The animal didn't cross the street because it was too tired”}  

\hfill 
 

What does “it” in this sentence refer to? Is it referring to 
the street or to the animal? It’s a simple question to a human, 
but not as simple to an algorithm.

When the model is processing the word “it”, self-attention 
allows it to associate “it” with “animal”.

As the model processes each word (each position in the input 
sequence), self attention allows it to look at other positions 
in the input sequence for clues that can help lead to a better 
encoding for this word.  

\begin{figure}[h!]
    \centering
    \includegraphics[width=0.5\linewidth]{Pictures/Transformer_Model/self_attention.png}
    \caption{Self Attention}\label{fig2:self_attention}
\end{figure}  

The main intuition behind this method is to compute the relative 
importance of a ciphertext character with respect to the other 
ciphertext characters. From our dataset containing encrypted 
text and the algorithm used for encryption, we create a text 
prompt from each row for example: 

\begin{flushleft}
    Cipher text: \texttt{ymccaygimgamkyyiycuycqocyeagmigkycmyyoyy}\\
    Algorithm: \texttt{affine}
\end{flushleft}

The model learns the relative importance of each token and uses 
it to predict the next. For example, if the model is trained 
with the above prompt and then we supply the following prompt: 

\begin{flushleft}
    Cipher text: \texttt{yycmdkreqluithnalekstndonwothvn}\\
    Algorithm: 
\end{flushleft}

The model shall generate the output as “affine” which it learned 
from training. 

\hfill

In our use case, we have used the GPT-Neo (Generative Pre-Trained) 
model with 125 million parameters to achieve our objective.  
It consists of stacks of encoders and decoders put one after 
the other, of which has been pre-trained on Wikipedia Corpus 
as well as Common Crawl (This has over 12 Petabytes of data 
which is 12 years of data uploaded on the internet) datasets 
for performing extremely well on language-based use cases. 
Generative, as the word suggests, is for making our code generate 
text. The architecture is similar to GPT2 except that GPT Neo 
uses local attention in every other layer with a window size 
of 256 tokens. All these models are available for free in the 
Hugging Face transformers library which can be used for a 
variety of NLP tasks.

\newpage

The following steps were taken for this model:
\begin{enumerate}
    \item   Each data of the dataset is converted into text prompts 
            that is passed through a tokenizer that creates embedding 
            for each token in our input string. 
    \item   The input dataset has been split into the ratio 
            80:10:10 for training, testing, and validating purposes.
    \item   The training and validation set has been used to 
            fine-tune the model’s hyperparameters specific to 
            our use-case i.e.\ detecting the algorithm used in 
            the ciphertext generation.
    \item   We used the fine-tuned model on our test dataset 
            to check the accuracy of our model. 
\end{enumerate}

For our testing purpose, we used various decoding strategies 
to find the one which gives the best result. Out of the strategies: 
Greedy Search, Beam Search, and Sampling with set temperature, 
we found sampling to give the most accurate results of all three. 
It is a method that is in between the greedy and sampling approach.

The greedy method selects the next token that has the highest 
probability as the output while sampling selects one of the 
possible next tokens randomly. When we set a temperature, the 
randomness is lowered such that the likelihood of high-probability 
words are increased and that of the low probability are decreased. 
We found that a \textbf{temperature set to 0.7} gave the optimum accuracy 
on our test data.

\section{CONCLUSION}

This report shows the current progress of our work in the detection of ciphertext using Artificial Neural Networks. Here we used two types of Neural Networks to achieve our objective, namely: Convolution Neural Networks and Transformer approach. 

With the CNN approach, our model was able to achieve an accuracy of 61.90\% for 5 class classifications. We saw a significant improvement with the transformers approach on the same dataset and classes giving an accuracy of 83.24\%. This was primarily due to the higher number of parameters of Gpt-neo and the ability to memorize the local importance of tokens due to the self-attention feature. 

In future work, we would like to extend the number of classes of ciphertext and also increase our dataset to find how our models perform in the new environment. We would like to try a feature-learning approach and also use more transformer models.  We would also like to solve the Cipher ID challenge from Mystery Twister C3  consisting of 500 ciphertexts. Based on our results and improvements, we would like to publish our work in a journal to see how our results stand in global competition.
